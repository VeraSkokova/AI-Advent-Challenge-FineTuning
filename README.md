# 🔥 Отчет по заданию: День 10. Micro-model first

## 📌 Описание задачи
Выбрана задача **извлечения простых данных** (категоризация тикетов техподдержки).
Цель пайплайна — проанализировать текст тикета и извлечь структурированный ответ в формате JSON:
- `type` (Incident / Request / Problem / Change)
- `priority` (high / medium / low)
- `language` (код языка, например, `en` или `de`)

Традиционно для таких задач по умолчанию используют большие LLM. В данном решении реализован двухуровневый инференс, чтобы доказать, что большинство запросов можно закрыть быстрой и дешевой локальной micro-моделью.

---

## 🏗 Архитектура решения (Kotlin + Ollama)

### 🔹 Уровень 1 — Micro-model (`qwen2:1.5b`)
Маленькая локальная модель, работающая в строгом JSON-режиме (`format="json"`).
Помимо самих данных, модель возвращает **статус уверенности**:
- `confidence` (0.0 - 1.0)
- `status` (`OK` / `UNSURE`)

**Логика:** Модель получает строгие инструкции возвращать `UNSURE` и низкий `confidence` для слишком коротких (менее 2 предложений) или двусмысленных тикетов.

### 🔹 Уровень 2 — LLM Fallback (`llama3.1:8b`)
Большая модель вызывается **только если**:
1. Micro-модель вернула статус `UNSURE`
2. `confidence` оказался ниже заданного порога (`< 0.75`)
3. Micro-модель вернула невалидный JSON или нарушила структуру полей

## 📊 Тестирование и Метрики

Для тестирования был подготовлен датасет из **30 тикетов**, разделенный на 3 категории по сложности (по 10 штук):
- `simple` (понятные и однозначные)
- `borderline` (короткие или смешанные признаки)
- `complex` (длинные тексты, медицинская/финансовая специфика, неочевидная причина)

### Итоговые замеры инференс-пайплайна
* **Всего запросов:** 30
* **Обработала micro-model (`qwen2:1.5b`):** 28 тикетов (93%)
* **Ушло в fallback (`llama3.1:8b`):** 2 тикета (7%)
* **Общее количество сэкономленных вызовов большой LLM:** 28

### Замер Latency (скорость ответа)
* **Средняя latency micro-model:** ~850–950 мс
* **Средняя latency fallback:** ~1600–5300 мс

> **Вывод по производительности:** Micro-модель работает в 2–5 раз быстрее тяжелой LLM, при этом успешно справляется с 93% потока. Fallback-механизм надежно страхует пайплайн на сложных пограничных кейсах.
