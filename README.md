# 🚀 День 6. Подготовка Dataset для Fine-Tuning

Решение первого практического задания по дообучению LLM. 

## 1. Выбранная задача
**Генерация:** Автоматические ответы службы поддержки на тикеты пользователей. 
Модель должна отвечать вежливо, профессионально, по делу, без "воды" и галлюцинаций, строго придерживаясь корпоративного стиля.

## 2. Сбор и подготовка датасета
В качестве источника использован открытый датасет с обращениями в службу поддержки. 
- Извлечено **50 реальных примеров** на английском языке (для оптимизации расхода токенов и ускорения обучения).
- Данные приведены к формату OpenAI (JSONL), где каждая строка содержит массив `messages` с ролями:
  - `system`: задает контекст ("You are a customer support agent...").
  - `user`: исходный тикет пользователя.
  - `assistant`: эталонный ответ службы поддержки.
- Датасет очищен и разделен на две выборки:
  - `train_tickets.jsonl` — 40 строк (80%).
  - `eval_tickets.jsonl` — 10 строк (20%).

## 3. Скрипт валидации
Написан консольный валидатор на **Kotlin** (`kotlinx.serialization`), который проверяет файлы перед отправкой в API:
- ✔️ Каждая строка является валидным JSON.
- ✔️ Присутствует массив `messages`.
- ✔️ В массиве есть все три обязательные роли (`system`, `user`, `assistant`).
- ✔️ Поле `content` не пустое ни у одной из ролей.

## 4. Замер Baseline
Для получения отправной точки (Baseline) 10 примеров из `eval_tickets.jsonl` были прогнаны через локальную модель **llama3.1:8b** с использованием Ollama (через OpenAI-совместимый API). Результаты зафиксированы в файле `baseline_results.txt`.

### Критерии оценки ("стало лучше"):
Анализ baseline-ответов выявил типичные ошибки базовых моделей. Успех файнтюна будет оцениваться по 3 критериям:
1. **Отсутствие выдуманных ссылок/плейсхолдеров:** Дообученная модель не должна генерировать конструкции вроде `[Insert attachment link]`.
2. **Отсутствие технических галлюцинаций:** Модель не должна выдумывать функции продукта, не описанные в промпте (например, выдуманная поддержка "labels and colors").
3. **Строгое соответствие формату:** Ответ должен подаваться сплошным текстом (абзацами), без генерации списков/буллитов и шаблонных расшаркиваний (`Dear [Customer]`).

## 5. Усиление: API-клиент для файнтюна
В рамках Kotlin-приложения реализован клиент на базе библиотеки `aallam/openai-kotlin`. 
Модуль автоматизирует весь процесс работы с OpenAI API:
1. `upload file` — загрузка `train_tickets.jsonl` с параметром `purpose = "fine-tune"`.
2. `create fine-tuning job` — создание задачи на дообучение.
3. `poll status` — опрос статуса выполнения задачи в цикле.

Для безопасной разработки клиент покрыт unit-тестами (с использованием `JUnit 5` и `MockK`), что позволяет проверять логику работы без реальных затрат API-кредитов OpenAI.
